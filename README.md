# green_innovation_screening
Classification model designed to rank green trademark candidates using public ISED data.

Each trademark is classified as **green**, **mixed** or **non-green** from its name, its goods/services text, its Nice classes and its Vienna codes. Trademarks are then ranked by how likely they are to be green. The current scope is ordinary trademarks registered in Canada in 2024.

## Data

All data comes from the CIPO *Trademarks researcher datasets* (release 2025-01-28, data up to 2025-01-22):
https://ised-isde.canada.ca/site/canadian-intellectual-property-office/en/canadian-intellectual-property-statistics/trademarks-researcher-datasets-applications-and-registrations-csv-and-txt

Field definitions and code meanings are in the data dictionary:
https://ised-isde.canada.ca/site/canadian-intellectual-property-office/en/trademarks-researcher-datasets-data-dictionary

| File | One row per | Used for |
|---|---|---|
| `TM_application_main_2025-01-28.csv` | application | Dates, mark name, mark type, trademark class |
| `TM_cipo_classification_2025-01-28.csv` | application × Nice class | Nice codes |
| `TM_applicant_classification_2025-01-28.csv` | application × goods/services text line | Goods/services description |
| `TM_representation_2025-01-28.csv` | application × Vienna code | Vienna codes (what a logo shows) |

All files are pipe-delimited (`|`) and joined on `Application Number`. Keep that column as text, because it has leading zeros.

## Workflow

### 1. Download the data

Download the four CSV zip files above from the dataset page, unzip them, and put the CSVs directly in `data/`, not in subfolders.

### 2. Build the 2024 pool — `data_cleaning/data_cleaning.ipynb`

The pipeline cell builds `pool/TM_registered_2024.csv`, one row per application number:

1. Reads `application_main` in 250,000-row chunks and keeps applications with a **registration date in 2024** (62,586).
2. Reads the other three files the same way and keeps only rows for those application numbers. Filtering first keeps memory low. Joining the full files first would need tens of GB.
3. Combines the rows of each file into one value per trademark:
   - **`Nice Code`**: its Nice classes, sorted and joined with `;`, e.g. `03;05;41`.
   - **`Goods Services Description`**: its goods/services statements, joined with ` || `. Statements longer than 4,000 characters are split over several rows in the source, and are first rejoined into one statement.
   - **`Goods Services Statements`**: the number of statements, usually one per Nice class.
   - **`Goods Services Items`**: the number of items, counted by splitting the statements on `;`.
   - **`Vienna Code`**: `category.division.section` codes joined with `;`, e.g. `26.4.2;29.1.1`. `-1` placeholders are dropped.
4. Writes the result with all application_main columns plus the columns above.

The source files never use quotes around fields, but some text starts with a stray `"`, so the source files are read with `quoting=csv.QUOTE_NONE`. The pool file is written with standard CSV quoting, so read it with:

```python
pd.read_csv(path, sep="|", dtype=str, index_col="Application Number")
```

The rest of the notebook keeps **ordinary trademarks only** (`Trademark Class Code == "1"`, 61,631 marks) and the model features, then explores them with charts.

### 3. Explore the data — end of `data_cleaning.ipynb`

The charts cover:
- trademarks per Nice code;
- trademarks per Vienna main category;
- goods/services statements and items per trademark (log scale);
- trademarks per mark type.

A separate cell lists the 604 marks with more than 200 items. These are mostly product catalogues copied into the filing; for example, ENERJO lists 29,781 items.

### 4. Add labels — `labels/labels.csv`

Labels are provided separately. The file has two columns:

```
Application Number,label
1505797,non-green
1990531,mixed
```

`label` is one of `green`, `mixed`, `non-green`. Labels should follow one written guide:
- *green*: all goods/services serve an environmental purpose;
- *mixed*: some do;
- *non-green*: none do.

Green marks are rare, so the labelled set should combine a **random sample**, used for evaluation, with **extra marks likely to be green** (e.g. keyword matches), so the model sees enough green examples. Record which sample each mark came from.

### 5. Train the baseline — `models/baseline.ipynb`

1. **Inputs**: mark name + goods/services text, Nice codes, and Vienna main categories (`26.4.2` → `26`).
2. **Features**, combined in one scikit-learn `ColumnTransformer`:
   - TF-IDF on the text: words and word pairs, accents stripped, `min_df=2`, `max_df=0.9`, sublinear term frequency;
   - multi-hot (0/1) columns for the 45 Nice classes and the 29 Vienna categories.
3. **Model**: logistic regression with `class_weight="balanced"`, compared against a dummy model that always predicts the most common class.
4. **Evaluation**: a stratified 80/20 split plus 5-fold cross-validation, reporting:
   - macro F1 (all three classes count equally);
   - average precision for green (how well the green marks are ranked);
   - a confusion matrix.
5. **Inspection**: the terms and codes with the largest weights for each class.
6. **Ranking**: retrains on all labels, scores every trademark with `green_score = P(green) + 0.5 × P(mixed)`, and saves the ranking and the model to `artifacts/`.

Until labels exist, set `USE_DUMMY_LABELS = True` to run the notebook on random labels. This only checks that the code runs; the scores are at chance level and mean nothing.

## Data notes

- **Trademark Class Code** gives the legal kind of mark: `1` = ordinary trademark; other codes are official/prohibited marks, certification marks, geographical indications, etc. (see the data dictionary). Only code `1` is modelled. The other codes mostly have no goods/services text.
- **MarkType Code** gives the mark format: `1` = word, `2` = figurative (logo), `3` = combined, etc. Logo marks usually have no name text.
- **Mark name**: use `Mark Significant Description`. It equals `Mark Verbal Element Description` wherever both are filled, and is filled more often.
- **Vienna codes** only cover some logos: 4,591 of the 61,631 ordinary 2024 trademarks. An empty value means "not coded", not "no logo". Category 29 (colours) appears on almost every coded logo.
- **Goods/services text** is in English or French (`Produits` = French goods statements).
- **Not in the data**: owner/applicant names, any green/environmental label, descriptions for the status codes, and logo images.
